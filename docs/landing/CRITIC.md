# MySet — What the audit itself missed

**Verdict.** The audit was thorough on the hero, the demo widget and the pricing block, but it left four whole classes untouched. (1) It never opened ask.png, the beat-3 screenshot — which shows a retired 3-vote credit pill, the retired $3 pack price, and is missing the ↗ link and the per-row + buttons that shipped after it was captured. (2) It never read the FAQ's money sentence at :683, 'nobody's out of pocket', which is falsifiable in code: a fan who bought a vote pack and whose request is declined after the next song starts permanently loses a purchased vote. (3) It cleared 'Print it once. It's good forever.' twice — once for artists, once for venues — when the artist guarantee is asserted only in a comment the code does not implement (a retired name is claimable and resolves to a stranger's page, not a 404) and the venue guarantee has no implementation at all. (4) It never diffed about.html against the Studio's own plan sheet, which is where the sharpest contradiction sits: studio.html sells 'Shows that start and end themselves' as a Plus/Pro feature while _auto.mjs contains no plan gate whatsoever, so every free artist already has it. On structural drift the answer is stark — no test in the repo reads public/about.html, while test/limits.mjs is a 200-line purpose-built guard pointed at studio.html, venue-studio.html, lock.css, app.css and admin.mjs, and test/copy.mjs already loops over every public/*.html for one word. The harness exists; the marketing page is simply not in it, which is precisely how :606 came to sell Plus-only setlists as free. Two smaller gaps worth logging: public/mp4trim.js (516 lines, the no-re-encode clip trimmer that keeps a fan's audio) is in no surface of the app index, and test/structure.mjs guards six Studio tabs when there are seven — the unguarded one being Merch, which about.html sells.

### [major] line 683 — about.html:683 (FAQ, 'What if they request something I can't play?'): 'declining refunds them automatically, so you're never the villain and nobody's out of pocket.'

'Out of pocket' is an explicit money claim, and it is false for any fan who bought a vote pack. A request is charged to me.spent (_requests.mjs:96). creditsUsed = sum(costOf(votes)) + spent (_lib.mjs:719). paidUsed = max(0, creditsUsed - freeCredits) (_lib.mjs:499-501). Every play/playTop is in RESETTERS (admin.mjs:1730) and fires clearAllFanVotes (admin.mjs:2001), which settles the paid portion — bag[id].extra -= paid — and then zeroes spent (_lib.mjs:517-521). The refund is me.spent = max(0, spent - cost) (_requests.mjs:141-143). So once a song has started, the request has already been paid for out of purchased credits and the later decline subtracts from a zeroed field and returns nothing. Worked example on shipped defaults: fan buys the 5-vote/$5 pack (extra=5); votes on three unplayed songs (creditsUsed 3); makes a 3-vote request (spent 3, creditsUsed 6). Artist starts the next song: paidUsed = 6-5 = 1, so extra drops 5 to 4 and spent goes to 0. Artist then declines. Nothing comes back and one vote the fan paid real money for is gone for good. The audit examined the softer line at :400 ('their votes come straight back') and its skeptic even identified this mechanism — then filed it as 'a code bug, not a wording problem on the landing page'. The wording problem exists; it is 283 lines further down, on a sentence nobody read.

*netlify/functions/_requests.mjs:96 (me.spent += cost), :141-143 (refund clamps at zero), :155-178 (resolveRequest); netlify/functions/_lib.mjs:499-501 (paidUsed), :517-521 (settle then zero spent), :719 (creditsUsed); netlify/functions/admin.mjs:1730 (RESETTERS includes play and playTop), :2001 (clearAllFanVotes).*

### [major] line 377 — about.html:377 (beat 1, the printed QR code): 'Print it once. It's good forever.'

A retired page name is not protected, and the code comment that says it is, is wrong. auth.mjs:451 deletes the old name from a.bySlug and :452-453 writes it into a.oldSlug. The comment immediately above (:449-451) claims 'It is not claimable by anyone else while it is here — pickSlug and setSlug both refuse a name already in bySlug.' Neither does: setSlug's only clash test is `const owner = a.bySlug[want]` (auth.mjs:441), and pickSlug's free() is `!RESERVED.has(v) && !reg.bySlug[v] && !reg.byId[v]` (_auth.mjs:96) — neither consults oldSlug, and the name was removed from bySlug two lines earlier. So the first new signup or rename that lands on that name takes it, and artistBySlug (_auth.mjs:82) resolves bySlug FIRST — meaning every printed table tent and poster then opens a STRANGER's live voting page, not a 404. The audit's skeptic bumped into this while refuting a different finding and explicitly declined to file it, reasoning that 'a stranger's page still answers the code, so print it once holds for the overwhelming case'. Sending a room to another artist's setlist is the worst outcome available, not an acceptable one.

*netlify/functions/auth.mjs:441 (bySlug-only clash check), :451 (delete a.bySlug[old]), :449-453 (the comment asserting a guard, and the oldSlug write); netlify/functions/_auth.mjs:96 (pickSlug free() ignores oldSlug), :82 (artistBySlug resolves bySlug first).*

### [major] line 543 — about.html:543 (venue tick-list, 'One code on the tables'): 'Tonight's music, your menu and your offers. Print it once.'

For venues there is no oldSlug mechanism at all — not a broken guard, an absent one. venueauth.mjs:148 is `if (old && old !== want) delete r.bySlug[old];` with no oldSlug write. venueBySlug (_venues.mjs:45-52) has no fallback. pickVenueSlug (_venues.mjs:58-68) has none. `grep -rn oldSlug netlify/functions/` returns five hits, every one artist-side. Separately, in the same function: venue setSlug never checks VRESERVED, while the artist path checks RESERVED at auth.mjs:439, so a venue can rename itself to api, community, merch or orders.
