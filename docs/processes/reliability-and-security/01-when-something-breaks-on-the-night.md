# When something breaks on the night

**Who:** the server, a fan in the room, the artist on stage; the founder the morning after. **Trigger:** a request throws, or a page misbehaves on somebody's phone. **Outcome:** the room can still vote (rule 1 — every failure degrades to that); what broke is written somewhere that outlives Netlify's 24-hour log; a fan can say so in one sentence without signing in; and the artist can read both sides of it in the Studio. **Until decision 0157 nobody was told.** Now the founder's Studio gets a push when the bell stalls, a payment stays owed, the errors pile up or the storage stops answering (i09).

The ranking rule for this whole tab: nothing may break the gig. The shape of every safeguard here is *catch it, note it, answer something honest, keep going*.

| i01 | Catch the uncaught throw | conditional | Automation | MySet server R | Netlify | Every public handler is wrapped in `guard(where, h)`: a throw becomes a 500 with one sentence — *"Something went wrong on our side — it has been noted"* — never a stack trace to a phone. `test/errlog.mjs` proves every public handler is wrapped. **A store that did not answer is not a bug to file** (decision 0142, INVARIANT 0hq): `readDoc` throws a `StoreError` when a read throws or takes longer than `READ_TIMEOUT_MS` (four seconds — shorter than the Blobs client's first five-second retry sleep, so a throttled read fails where it used to hang for up to twenty-five), and `guard` answers it **503 "busy"** with `Retry-After`, never cached, never a sign-out. A document that is simply not there is still the caller's empty fallback. Sixteen request handlers that had no `guard()` now have one; `artistpage` catches its own read and serves the page as it always was. Until then a failed read and an empty document were the same value to every caller — a board short of votes, fresh credits, a winner picked from partial votes, an artist signed out mid-gig. `src: _errlog.mjs guard; _lib.mjs readDoc, StoreError; decisions 0029, 0142; test/storefail.mjs` |
| i02 | Write it into the hour's document | database | Automation | MySet server R | Netlify | `logErr`: one document per hour under a computable key (`err_<ISO hour>`, so no `list()` — INVARIANT 1), capped at `KEEP_PER_HOUR` rows, each a cut-short message and stack plus a route and a fan id — never a body, never an email. Logging must never throw and never slow the failing request: a few CAS tries, then give up silently; the `console.error` line still reaches Netlify's own 24-hour log. **The store being down is the one failure this cannot record** — and since decision 0142 it does not try: `logErr` skips a `StoreError`, because the write would wait on the same failure while the caller holds a reply for it. The watch reports a store that does not answer as a problem of its own (i09). `src: _errlog.mjs logErr, hourKey; INVARIANT 0fb; decision 0142` |
| i03 | Keep the room voting | conditional | Automation | MySet server R · Fan I | Netlify | The degradation ladder, in order: payments off → the app works fully with no buy button (INVARIANT 9); a Stripe return that never comes back → `/api/confirm`, the webhook and the reconcile sweep are three independent paths to the same grant (→ *Money → Stripe events arriving*); a shard write that reports success without sticking → re-read and retry (§5.2 rule 4); a burst of voters → 12 fan shards; a script → the cast token bucket (→ *The gig → The room under load*). Added by the 2026-10-02 scale week: a webhook grant that fails → Stripe is answered with an error and redelivers, and the bell retries the payment within minutes (decision 0138, → *Money → Stripe events arriving* w12, w13); a read the store did not answer → 503 "busy", never an empty document (decision 0142, i01); the vote page keeps its last board, waits longer between tries, up to a minute, and sends a "busy" vote again with the same cast id (decision 0143, → *The gig → The fan's night* f03, f09); the Studio treats any 5xx as a dropped connection and keeps its last good screen, its sign-in and its timer (decision 0142, INVARIANT 16). Nothing on this list needs a person awake. `src: overview §1.11, §5.2; INVARIANTS 9, 16, 0hm, 0hq, 0hr; decisions 0138, 0142, 0143` |
| i04 | "Something wrong?" from the audience | form | Person | Fan R · MySet server R | Netlify | The link on the voting page. Public and anonymous like `/api/vote`: a device id, one sentence, and the last things the page itself saw fail. An empty report is refused (*"Say what went wrong first"*); the same device is thanked but not stored twice inside `BUG_EVERY`; a rejected report never looks like a failure to the fan — they were helping. `src: bug.mjs; vote.html` |
| i05 | Attach the server's last hours | database | Automation | MySet server R | Netlify | `saveBug` stores the fan's note under `bugs_<aid>` (capped at `KEEP_BUGS`) together with the last `BUG_HOURS` hourly error documents — so the report carries what the phone saw **and** what the server saw in the window before it. The error log is global per hour, not per artist: on a busy night a report includes other rooms' errors. Acceptable at today's scale; the first thing to change if it stops being. `src: _errlog.mjs saveBug; decision 0029 § What this makes harder` |
| i06 | Read the reports in the Studio | notification | Automation | MySet server R · Artist I · Founder I | Netlify | Studio → Money → the reports, under the money (`bugList`: it routes through `PLAN_ACTIONS` but sits behind the founder gate, so only the founding page's owner seat reads it — decision 0099; since decision 0100 the Studio draws the card for that seat only, so no other artist sees a card that could never fill). GATE-004 — *a bug reported by a fan can be traced without reproducing it* — is **done** on this step. `src: admin.mjs bugList; ledger GATE-004, P3-004` |
| i07 | The two hammers under Settings | task | Person | Artist R | Netlify | Studio → Settings → **If something looks wrong**: *Reload the Studio* and *Clear what's stored on this phone* (`hardReset`, throws away the offline copy, keeps the sign-in). Pull-to-refresh is the first hammer on every page (`pull.js`) — but it is JavaScript, so it cannot rescue a page whose JavaScript is broken; that is what the two buttons are for. `src: studio.html "If something looks wrong"; overview §5.8` |
| i08 | The service worker stands down | conditional | Automation | MySet server R · Fan I | Netlify | `sw.js` never caches anything under `/api` (a cached vote is a lost vote — INVARIANT 0aw), never precaches, and navigations are network-first — so a bad deploy is fixed by the next deploy, not by asking somebody in a bar to clear a browser (0ax). A page can post `myset-unregister` to make the worker quit entirely. **Agents do not touch `sw.js`** (AGENTS.md § Where you may work). `src: public/sw.js; INVARIANTS.md § The service worker` |
| i09 | Page somebody | notification | Automation | Scheduled jobs R · MySet server R · Founder I | Netlify | **Built, not live** (decision 0157, pull request #213). When one of the watch's answers changes (→ *Watching production* u09), `watch` pushes to **the owner seat of the founding page only**, through `notify` — the same push the Studio already uses, so there is nothing new to install. The titles: *"MySet's scheduler has stopped"*, *"N payments not delivered"*, *"N server errors in the last hour"*, *"MySet's storage is not answering"*, and *"MySet is back to normal"*. **Told on change, not on a timer**: once when a thing goes wrong, again every hour while it stays wrong (`AGAIN_MS`), once when it is right again; what has been told is kept in one small document, `watch`. A push that fails is logged and does not stop the watch. From outside, a failed check opens a GitHub issue labelled `uptime`, assigned to the repository's owner, which GitHub emails and pushes (→ u11). Two things to keep true: the limits in `_watch.mjs`, and the push subscription on the founder's phone. **Not checked:** a real push arriving on the founder's phone. **Still not detected:** a Stripe key that exists and is dead, which on 2026-09-08 was found by a fan tapping a buy button (→ *Watching production* u07, P3-008). `src: _watch.mjs watch; watchcron.mjs; _push.mjs notify; decision 0157 (the alerting 0029 left for later); test/watch.mjs` |
