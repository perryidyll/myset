# When something breaks on the night

**Who:** the server, a fan in the room, the artist on stage; the founder the morning after. **Trigger:** a request throws, or a page misbehaves on somebody's phone. **Outcome:** the room can still vote (rule 1 — every failure degrades to that); what broke is written somewhere that outlives Netlify's 24-hour log; a fan can say so in one sentence without signing in; and the artist can read both sides of it in the Studio. **Until decision 0157 nobody was told.** Now the founder's Studio gets a push when the bell stalls, a payment stays owed, the errors pile up or the storage stops answering (i09).

The ranking rule for this whole tab: nothing may break the gig. The shape of every safeguard here is *catch it, note it, answer something honest, keep going*.

| i02 | Write it into the hour's document | database | Automation | MySet server R | Netlify | `logErr`: one of `ERR_SHARDS` documents per hour, picked at random, under computable keys (`err_<ISO hour>` and `…_1`–`…_3`, so no `list()` — INVARIANT 1; decision 0187), each capped at `KEEP_PER_HOUR` rows and counting every row past the cap (`n`), each a cut-short message and stack plus a route and a fan id — never a body, never an email. Logging must never throw and never slow the failing request: three CAS tries, each on a different shard, then give up silently; the `console.error` line still reaches Netlify's own 24-hour log. **The store being down is the one failure this cannot record.** `src: _errlog.mjs logErr, hourKey; INVARIANT 0fb` |

Nothing on this list needs a person awake. `src: overview §1.11, §5.2; INVARIANT 9` |
| i04 | "Something wrong?" from the audience | form | Person | Fan R · MySet server R | Netlify | The link on the voting page. Public and anonymous like `/api/vote`: a device id, one sentence, and the last things the page itself saw fail. An empty report is refused (*"Say what went wrong first"*); the same device is thanked but not stored twice inside `BUG_EVERY`; a rejected report never looks like a failure to the fan — they were helping. `src: bug.mjs; vote.html` |
| i05 | Attach the server's last hours | database | Automation | MySet server R | Netlify | `saveBug` stores the fan's note under `bugs_<aid>` (capped at `KEEP_BUGS`) together with the last `BUG_HOURS` hourly error documents — so the report carries what the phone saw **and** what the server saw in the window before it. The error log is global per hour, not per artist: on a busy night a report includes other rooms' errors. Acceptable at today's scale; the first thing to change if it stops being. `src: _errlog.mjs saveBug; decision 0029 § What this makes harder` |

| i08 | The service worker stands down | conditional | Automation | MySet server R · Fan I | Netlify | `sw.js` never caches anything under `/api` (a cached vote is a lost vote — INVARIANT 0aw), never precaches, and navigations are network-first — so a bad deploy is fixed by the next deploy, not by asking somebody in a bar to clear a browser (0ax). A page can post `myset-unregister` to make the worker quit entirely. **Agents do not touch `sw.js`** (AGENTS.md § Where you may work). `src: public/sw.js; INVARIANTS.md § The service worker` |
| i09 | Page somebody | notification | Automation | Scheduled jobs R · MySet server R · Founder I | Netlify | **Live** as `b7444c4` (decision 0157, PR #213). When one of the watch's answers changes (→ *Watching production* u09), `watch` pushes to **the owner seat of the founding page only**, through `notify` — the same push the Studio already uses, so there is nothing new to install. The titles: *"MySet's scheduler has stopped"*, *"N payments not delivered"*, *"N server errors in the last hour"*, *"MySet's storage is not answering"*, and *"MySet is back to normal"*. **Told on change, not on a timer**: once when a thing goes wrong, again every hour while it stays wrong (`AGAIN_MS`), once when it is right again; what has been told is kept in one small document, `watch`. A push that fails is logged and does not stop the watch. From outside, a failed check opens a GitHub issue labelled `uptime`, assigned to the repository's owner, which GitHub emails and pushes (→ u11). Two things to keep true: the limits in `_watch.mjs`, and the push subscription on the founder's phone. **Not checked:** a real push arriving on the founder's phone. **Still not detected:** a Stripe key that exists and is dead, which on 2026-09-08 was found by a fan tapping a buy button (→ *Watching production* u07, P3-008). `src: _watch.mjs watch; watchcron.mjs; _push.mjs notify; decision 0157 (the alerting 0029 left for later); test/watch.mjs` |
