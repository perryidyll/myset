# Sessions, roles and the team

**Who:** the account owner managing seats; any signed-in person managing their own devices. **Trigger:** Settings → Signing in / team members. **Outcome:** a band mate can run a show and never take the account; the owner decides, seat by seat and tab by tab, what each one can see and change; one phone can be signed out without signing out the band; and there is a record of what happened.

Two of the holes this closed were ways to lose an account: a member could delete the owner's address or rename the public page every printed QR code points at; and sign-out cleared the browser and told the server nothing, so a copied token worked for a month.

| t01 | Resolve the role on every request | conditional | Automation | MySet server R | Netlify | `byEmail[email].role` → `CAN` in `_session.mjs`, the one table that says what a role means. **owner** = everything (money, plan, payouts, access, the page address, recovery codes, export, deletion). **member** = the page and the show, and the activity log (`audit`, the one name left in `CAN` besides the tabs). **crew** = tonight only: run the show, see the Setlist, the queue and requests. **An unknown role falls back to `crew`** — default-deny, so a string the table has never heard of can never be an escalation; the lookup is an own-property check because `CAN['toString']` is an inherited Function. **Each seat, each tab (decision 0105):** the role is the seat's preset. The owner can set each of nine Studio tabs (Setlist, Gigs, Money, Merch, Diary, Messages, Profile, Settings, Plans) to 0 hidden, 1 view or 2 edit per seat (`byEmail[email].access`, only what differs from the preset). `can(role, 'money_view', access)`. The Setlist is never below view, Plans never above view, and running the show and the requests belong to every seat; `OWNER_ONLY` is checked first and no grant reaches past it. Presets: member edits every tab but Money and Plans (view); crew sees the Setlist. In `admin.mjs` the `CAPABILITY` and `OWNER_ONLY` rows are **deny-lists** — an action they do not name needs only a sign-in — so every name in them must be an action a handler takes; `test/structure.mjs` refuses one that is not (decision 0099: seven rows had named no handler, and crew could rewrite setlists, charts, lyrics and genres). Every `CAPABILITY` row names a tab and `_view` or `_edit`. Venues: owner / manager / crew. `src: _session.mjs AREAS, PRESET, levelOf, CAN; admin.mjs CAPABILITY, OWNER_ONLY; ACCOUNTS.md §6.3, §6.3a; decisions 0099, 0105` |
